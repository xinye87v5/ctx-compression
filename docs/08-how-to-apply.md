# 08 · 怎么把它用在你自己的语料上

> 前七篇回答"信不信"；这一篇回答"**做不做得到**"。
>
> 目标：让你在**半小时内**从自己已有的会话日志里，算出**可与本文档集对照**的第一个数。
> 全部内容不依赖我们未发布的工具链 —— 公式、阈值、顺序都在这里。

---

## 一、三个指标的操作定义

**没有可执行定义的指标等于没有指标**：读者按自己的理解算出一个数，既不知好坏，也无法与别人对照。
所以三个指标一律给**公式 + 阈值 + 为什么这么定**。

### 1.1 逐字覆盖（主指标）

| 项 | 定义 |
|---|---|
| **单位** | 窗口内的**用户发言**（不是 agent 发言、不是工具结果） |
| **归一化** | 去首尾空白、折叠连续空白；长度按归一化后的**字符数** |
| **分母** | 归一化长度 **≥ 阈值** 的用户发言。**短于阈值的必须剔除** |
| **判据** | `LCS(发言, checkpoint) ≥ 阈值` ⇒ 记 1，否则 0 |
| **两档** | **严格：阈值 30 字符**（主指标）｜**宽松：阈值 12 字符** |
| **报告** | 必须同时报：`覆盖 = 命中/分母`、`均 lcs/len`、**分母大小** |

**为什么必须剔除短发言**：`LCS ≥ 30` 对一条 4 字符的「好的」是**数学上不可达**的。
不剔除，这些发言会一律记 0，把分母污染成"消息太短的惩罚"。
实测某窗口 30 条发言里**合格分母只有 5 条** —— 不查这一步，整个读数毫无意义。

**为什么严格才是主指标**：宽松档会把"保住了 12 个字符"也算过。
它的作用是**暴露差值**（严格与宽松差得越多，说明摘要越依赖"换句话重述"而不是逐字保留）——
而"重述"恰恰是这类系统最危险的行为：它丢失可核对的真值。

**必须同时看 `均 lcs/len`**：一条极长发言可以吃掉窗口内全部字符的绝大部分
（实测：1 条 1,861 字符的发言占 83.6%），于是"覆盖率"基本只在反映那一条。

### 1.2 所指有痕（补上"回指式发言"）

**它解决什么**：长期协作里大量发言是「同意」「可以」「就按刚才那个」——
逐字抄下来得满分，但下一个模型**不知道同意的是什么**。

| 项 | 定义 |
|---|---|
| **对象** | 归一化长度 **≤ 12 字符** 的发言（回指型），以及长度 **≥ 20 字符** 的（自足型） |
| **参照物** | 该发言**上一条 agent 消息**的**末 2,000 字符** |
| **度量** | 把参照物切成 **12-gram** 集合，算其中出现在 checkpoint 里的比例 |
| **判据** | 比例 **≥ 10%** 记"所指有痕迹" |
| **中间带** | 12 < 长度 < 20：**只报告，不判定**（避免事后挪阈值） |

**为什么用 n-gram 而不是 LCS**：agent 消息可达上万字符，LCS 是 `O(n·m)`，这个规模上不可行。
n-gram 集合交集是本量的**代理指标**，因此它只能当**方向证据**，不能当精确读数。

### 1.3 自身存活

短发言"自己还在不在"：`LCS(发言, checkpoint) ≥ 8`。
它与"所指有痕"必须**分开报** —— 一个测"话还在不在"，一个测"话指向的东西还在不在"。
实测中最常见的失败是：**前者接近满分，后者恒为 0**。

## 二、一条最小可跑的路径（约 30 分钟）

前提：你手上已经有**真实使用过的 agent 会话日志**，且其中至少发生过一次压缩。

```
第 1 步  定位一次压缩边界
        在日志里找"压缩开始 / 摘要替换历史"那一刻。
        找不到显式事件，就用替代判据：上下文体积突然大幅回落的那一步。
        记下两条 seq：压缩前的最后一条、压缩后的第一条。

第 2 步  取两份文本
        · 发言序列：边界之前、该窗口内的全部【用户】发言
        · checkpoint：边界处产生的那段摘要文本

第 3 步  算第一个数：严格逐字覆盖
        对每条发言算 LCS(发言, checkpoint)；≥30 记 1。
        分母 = 归一化长度 ≥30 的发言数。

第 4 步  立刻做分母自检（这一步最容易被跳过）
        分母 < 5 ⇒ 这次测量**无效**，换一个更长的窗口重来。
        分母在 5–10 ⇒ 只报告，不下结论。
```

**到此你已经有了第一个可比数字。** 接下来才有意义去谈改进方案。

## 三、要多少数据才敢下结论

这是本方法论里**最容易被忽略、代价最高**的一段。
我们自己的历史上，n=1–3 的读数被当成结论、后来又撤回的事发生过不止一次。

| 用途 | 最低门槛 | 为什么 |
|---|---|---|
| **描述性观察** | 任意 | **只报告，不下结论** —— "我们看到 X" 是允许的，"X 成立"不是 |
| **单窗口保真度** | 合格分母 **≥ 10** | 低于此，"覆盖率"由个位数发言决定 |
| **两臂配对对照** | 每臂 **≥ 3 次** | 3 vs 3 的精确置换检验，双侧下限就是 p=0.05 |
| **会话级 cluster bootstrap** | **≥ 8 个簇** | 少于 8 个簇，置信区间宽到无法区分任何假设（实测 7 簇时 CI 跨 0 且宽达 ±0.5） |
| **下游行为验证** | **≥ 10 次生产压缩** | 抱怨率这类下游量本身很稀疏，少于此功效不足 |

**三条纪律**：

1. **低于门槛只准报告，不准下结论。** 写"n=3，方向一致，探索性"是可以的。
2. **配对设计优先于扩样本。** 实测中，把样本从 10 个会话扩到 41 个，反而因为对照人群错配让效应"消失"——
   **规格比样本量更决定结论**。
3. **同一前缀至少重复 3 次**，把"臂间差异"与"跑一次的运气"分开。
   实测同一臂三次的极差（0.107–0.168）**与声称的效应量（0.156）同量级** —— 不重复根本分不开。

## 四、出数之后先问三个问题

按顺序问，任何一个不过就停下来查，**别急着解释结果**。

| # | 问题 | 不过关的信号 | 怎么办 |
|---|---|---|---|
| **1** | 这个量级**荒谬**吗？ | 比例 >100%、恒 0、恒 1、报告比原文还大 | **先当 bug 查，再当发现**。实测靠这一条抓到过"报告比原文侧大 350%"的实现 bug |
| **2** | **分母**对吗？ | 分母只有个位数、分母里混进了不该算的东西 | 回到 §1.1 的剔除规则；再查"每条发言对应的步数"是否被忽略了（曝光单位选错实测把效应放大 1.7 倍） |
| **3** | **反证能变红**吗？ | 故意把功能关掉，指标**没有变化** | 说明**用例没测到东西**，不是实现没问题。把断言改成可观察行为后重跑 |

**第 3 条最反直觉**：它检验的不是实现，而是**你的测试**。
一个恒真的断言（比如断言某个函数存在，而那是你自己赋的值）会让整套检查变成安慰剂。

## 五、一次完整走样（合成语料）

用一个编造的窗口演示全流程。假设压缩前窗口内有 6 条用户发言：

```
#   用户发言（归一化后）                        长度   LCS(发言, checkpoint)
1   "帮我看看这个模块的依赖关系"                    13     4
2   "可以"                                          2     —（不合格，剔除）
3   "把配置文件里的超时改成 30 秒，原来那个太短了"      21    19
4   "同意"                                          2     —（不合格，剔除）
5   "刚才那个报错是因为路径写错了，应该用绝对路径"      21    21
6   "就按你说的办"                                    6     0
```

**计算**：

| 指标 | 计算 | 结果 |
|---|---|---|
| 严格逐字覆盖 | 分母 = {3, 5}（仅长度 ≥30 的两条……**此处即暴露问题**） | 见下 |
| — | 实际上 1/3/5/6 的长度都 < 30 ⇒ **合格分母 = 0** | **本次测量无效** |

**这就是这一步的价值**：第一次算就会撞上"**合格分母为 0**"。
说明**这个窗口太短，不能用来测严格保真度** —— 需要换更长、发言更长的窗口。

换一个窗口后（合格分母 12）：

| 指标 | 读数 | 解读 |
|---|---|---|
| 严格逐字覆盖 | 7/12 = **58.3%** | 主指标 |
| 宽松逐字覆盖 | 10/12 = 83.3% | 与严格差 25pp ⇒ **摘要大量依赖"换句话重述"** |
| 均 lcs/len | 0.61 | 排除"被单条长发言支配" |
| 短发言（≤12 字符）自身存活 | 4/5 = 80% | 话还在 |
| **短发言所指有痕** | **0/5 = 0%** | **话在，但不知道在说什么** |

最后一行是关键：**如果只报"逐字覆盖 58.3%"，你会以为一切正常**。
补上"所指有痕"才看见真正的缺陷 —— 这正是本文档集的核心发现。

## 六、不该照抄的三件事

1. **不要照抄触发阈值。** 阈值是引擎实现细节，会随版本与模型变化。
   要抄的是**方法**：先量出你自己的触发带，再看它是否落在"该压的位置"上。
2. **不要照抄改进后的提示词。** 我们的指令是**对着自己的指标写的** ——
   换了指标它就未必最优，甚至可能更差（实测同一批指令在不同口径下排序会反转）。
3. **不要在没有召回通道时把"不压缩"当对照。** 不可逆的压缩与"保留全部历史"不是同一个系统，
   两者的下游行为不可直接比较；先确认你有办法把丢掉的东西找回来，再谈优劣。
